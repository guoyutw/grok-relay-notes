# 我不想再幫 AI 複製貼上訊息了

**所以我試著讓 ChatGPT 和 Grok Bot 直接對話。原本以為接起來就好，結果光是確認「話有沒有送到、工作到底做完沒」，就踩了一堆坑。**

這是我的 AI 協作實驗紀錄，不是產品發表，也還不是一個可以直接安裝的工具。

## 我原本只想省下複製貼上的動作

我平常用 ChatGPT 討論想法、整理專案，也開始用 Grok Bot 做研究。有時想知道 Grok 對 ChatGPT 結論的看法，就把這邊的訊息貼過去，再把那邊的答案貼回來。

貼著貼著，我就在想：

**「為什麼不能讓它們自己講？」**

**以前：** ChatGPT → **我複製貼上** → Grok Bot → **我再貼回來** → ChatGPT

**我想要的：** ChatGPT ⇄ Grok Relay ⇄ Grok Bot

我用 OpenChatX 讓 ChatGPT 能操作本機工具，再接上既有的 Grok Bot。希望不只訊息送得過去，還能確認回覆屬於哪一件工作、對方是不是真的做完了。

## 沒想到，真正麻煩的才剛開始

### ① 訊息傳過去了，內容卻不見了

我送的是包含背景的多行需求，Grok Bot 卻只收到要求句。訊息看似成功送出，實際上對方根本沒拿到完整問題。

### ② Grok 明明回答了，ChatGPT 卻不知道

有一次系統顯示還在處理，後續查詢又被擋住；但 Grok Bot 那端其實已經收到並回覆。

這時候最不能做的，就是以為失敗了再傳一次——有可能讓它把同一件工作做兩遍。

### ③ 我只是跟 Grok 聊天，卻把之前完成的任務搞壞了

一筆工作已經完成，我又在同一個對話裡跟 Grok Bot 普通聊天。結果兩則聊天回覆被 Relay 讀進來，讓原本完成的工作被錯誤標成異常。

我才發現：**能傳話，和能可靠地合作，是兩回事。**

這些問題都是實際遇到的，不是為了寫架構而假想出來的。細節和後來的修正記在 [踩坑紀錄](EVOLUTION.md)。

## 現在做到哪裡？

**目前已成功完成一次「ChatGPT 發出測試請求 → Grok Bot 回覆 → 系統確認完成」的來回。** 我也已經把專用的 Grok Relay 環境架好、確認本地連線設定，但**還沒驗證從新環境再實際送一筆訊息的完整結果**。

所以還不能說兩個 AI 已經能長時間、無人看管地自行討論或合作。這是接下來要驗證的事。

## 這個 Repo 放什麼？

- **[PROTOCOL.md｜協議筆記](PROTOCOL.md)**：怎麼標記每一筆請求、區分「還在做」和「真的做完」，以及訊息狀態不明時為什麼不能亂重送。

我對 ChatGPT 的使用脈絡比較長；較近期才開始用 Grok Bot，主觀感覺它有時能帶來不同角度或反例。這是**後來才明確整理的觀察**，不是一開始就證明它們誰比較聰明、誰比較客觀。
