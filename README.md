# Grok Relay

> **Experimental / Work in progress**
>
> 這是一份開發紀錄，不是已完成的開源產品，也沒有可直接套用的安裝包。最後整理：2026-11-01。

## 為什麼做？

我原本用 ChatGPT 討論、規劃和整理長期專案脈絡，讓 Hermes 協助工程工作，也開始用 Grok Bot 做研究。

**我不想一直當這些 AI 之間的人工轉貼員。** 所以我試著讓 ChatGPT 能直接與 Grok Bot 溝通。

原本以為訊息能送過去就夠了，實際卻遇到多行內容遺失、發出後不確定對方有沒有收到、傳輸結束卻不代表工作完成，甚至日常聊天干擾已完成的委派狀態。這個實驗便從單純訊息橋接，慢慢延伸到請求識別、明確完成訊號和故障處理。

## 這裡分享什麼？

- [EVOLUTION.md](EVOLUTION.md)：幾次實際發生的問題、我們怎麼判斷，以及仍然未知的部分。已改寫為不依賴私人 Issue 連結的自足紀錄。
- [PROTOCOL.md](PROTOCOL.md)：從過程中提煉的 Request ID、progress/final、狀態隔離等設計原則，附簡化範例。

這裡主要是**一件作品的開發紀錄**，不是要另外經營電子報、技術網站或承諾長期維護。

## 目前狀態

- **已驗證：** 既有 Grok Bot 的委派／完成協議測試；專用 Grok Relay bot 在隔離環境中的首次聯絡與帶標記 final 回覆；獨立專用執行環境部署及本地路由綁定的驗證。
- **尚未驗證：** 從新部署的專用環境再次實際傳送 Grok 訊息並驗證遠端回覆交付，以及長期穩定的跨 AI 自主協作。
- **不提供：** 可直接安裝的套件、公開執行環境、正式維護承諾。

## 為什麼讓不同 AI 合作？

我對 ChatGPT 的使用脈絡比較長；較近期開始用 Grok Bot，主觀上感覺它有時帶來不同角度或反例。這是後來記錄的使用觀察，**不是**最初做 Relay 時就已驗證的模型能力優劣，也不是兩者的客觀排名。

## 證據與隱私界線

原始工程 Issue、程式碼、審查與 runtime 記錄目前保存在**未公開的工作專案**。這個 Repo 只放去識別化、重新敘述的案例，不附私人來源的無法開啟連結；完整原始證據尚未公開，因此外部讀者無法獨立核對全部細節。

未經另外確認，本 Repo 不公開憑證、原始對話、個人資訊、session / agent 識別碼、電腦路徑或生產環境紀錄。未來是否公開程式碼、增加實驗或繼續更新，都還沒有承諾。
